# 让 DSH 自己安装这套桥接

这个仓库是给 **DeepSeek Harness（DSH）agent** 读的。  
人类只需要把仓库交给 DSH，并说清楚目标。

## 推荐方式

### 1. 把仓库拿到本机

任选其一：

- 下载仓库 zip 并解压；
- `git clone` 到本地；
- 在 DSH 里打开这个目录作为工作区。

### 2. 对 DSH 说这段话

```text
请先阅读当前目录的 AGENTS.md、README.md、docs/versions.md、
docs/tutorial.md 和 docs/install-with-dsh.md。

目标：在这台 Windows 机器上把「鲸鱼娘 × DSH 桥接」装好并验证。
先只做最小链路：DSH 插件 → 鲸鱼娘网页聊天 → DSH 回复。
微信私聊/群聊/文件/B站等扩展先不做。

要求：
1. 先检查环境，不要猜；把 DSH profile、鲸鱼娘目录、Python/Node、
   8787/8789 端口、已有插件和桥接进程列出来；
2. 修改任何已有文件前先备份，并告诉我备份路径；
3. 不要覆盖新版鲸鱼娘的 src / examples，先用补丁脚本；
4. 每一步验证后再做下一步；
5. 需要我决定的事情一次问完；
6. 不要打印、提交或上传任何 API Key、Cookie、settings.json、auth.json；
7. 最后按 AGENTS.md 的报告格式汇报。
```

### 3. DSH 应该先回答什么

合格的第一轮回复应包含：

- 目标机器环境；
- 插件是否已经安装；
- 鲸鱼娘版本和目录；
- 8787 / 8789 状态；
- 计划步骤；
- 需要你确认的少数问题（工作区、权限、`brain` 选择）。

如果 DSH 直接开始复制文件/改配置，没有先检查环境，打断它，让它按 `AGENTS.md` 重新来。

## 理论上能到哪一步

**能稳定复现的：**

- DSH 原生聊天（鲸鱼娘网页/微信文字 → DSH 会话）；
- DSH 工具任务；
- 插件面板、聚合状态、一键启动；
- 流式 text 和任务回执（取决于 DSH 输出事件）。

**需要额外合并/配置的：**

- 微信文件进出；
- 群聊 @/引用/上下文处理；
- Win32 发送器、会话验证；
- B 站视频理解（还要本地 Cookie）。

**不包含、也不该由教程保证的：**

- 群聊概率、主动消息、人设等个人配置；
- 其他机器上的微信版本行为；
- 新版鲸鱼娘的 UI/源码差异；
- 任何凭据、账号、API Key。

所以：**核心桥接可以按教程复现；完整功能是参考实现 + 版本适配，不是 100% 一键复刻。**

## 最小链路验收

```text
[ ] DSH 能启动
[ ] 插件 8789 可访问 /api/health
[ ] 鲸鱼娘 8787 可访问 /api/status
[ ] 插件 /api/state 的 status.chain.online == true
[ ] 鲸鱼娘网页聊天能收到 DSH 回复
```

最小链路没通过前，不要开微信。

## 第二阶段：微信私聊

通过最小链路后再对 DSH 说：

```text
现在继续第二阶段：接微信私聊。
先确认微信 4.x 已登录、桥接脚本和依赖存在；
按 docs/tutorial.md 的「微信接入」部分做；
只测一个私聊，不要先动群聊。
```

验收：

```text
[ ] 微信私聊能收到回复
[ ] 发送失败时有日志，不会发到错误会话
```

## 第三阶段：群聊/文件/扩展

按需再开：

- 群聊 @/叫名字/引用；
- 文件进出；
- B站视频理解；
- 主动消息/定时任务。

这些都不是最小链路的必需项。

## DSH 需要向人类确认的信息

一般只需要一次问清：

1. DSH profile 用哪个（默认 desktop 还是其他）；
2. 工作区目录；
3. 权限：`workspace-write` 还是 `danger-full-access`；
4. 大脑：`brain=dsh` 还是 `upstream`；
5. 是否现在接微信。

其他技术细节让 DSH 自己检查，不要让人填一堆配置。

## 如果 DSH 卡住

让 DSH 按层报告：

```text
1. DSH 插件层：8789 /api/health
2. 鲸鱼娘层：8787 /api/status
3. 桥接层：/api/state 的 status.chain
4. 聊天层：网页聊天是否回复
5. 微信层：私聊是否回复
```

不要让它连续重启或重复启动桥接。

## 安全边界

- 不要把 8789 暴露到公网；
- 不要使用主微信账号；
- `danger-full-access` 需要明确同意；
- 仓库不包含凭据；配置和密钥只放本机；
- 任何需要打印 Token 的命令，都应改成“只报告是否存在”。
