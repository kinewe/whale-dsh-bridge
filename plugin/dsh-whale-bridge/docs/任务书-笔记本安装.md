# 任务书：把「DSH × 鲸鱼娘桥接」装到笔记本

> 目标：在另一台笔记本上复现本机的集成——DSH 桌面端 + 鲸鱼娘聊天壳 + 桥接插件，并保留后续「文件通道」的规划。
> 本文件是操作清单；接口细节见 `CONTRACT.md`，日常使用见 `README.md`。

---

## 0. 一句话流程

拷贝插件目录 → 改两个路径 → 跑 `install-dsh-plugin.ps1` → 刷新 DSH 页面 → 面板填上游 Key → 点「接入鲸鱼娘」→ 打开鲸鱼娘网页测试。全程不需要重启 DSH（HMR 热生效）。

---

## 1. 笔记本前置

| 需要 | 说明 |
|---|---|
| DSH 桌面端已安装并能打开 | 安装位置不限；插件通过 `process.execPath` 自动定位安装目录 |
| DSH 已有 `desktop` profile | 一般首次启动桌面端就会生成；路径 `%USERPROFILE%\.dsh\profiles\desktop` |
| 鲸鱼娘（whale-girl）完整包已解压 | 解压到**纯英文路径**（她自己的要求，中文路径会导致微信侧发送异常）；记下绝对路径 |
| 鲸鱼娘能正常聊天 | 先在她网页「设置」里填好模型 Key 并试一句，确认原始聊天链路 OK |
| 端口 8789 空闲 | 桥接默认端口；被占用会自动顺延并写回设置（面板可看实际端口） |

不需要：Node.js、pnpm、Python（桥接用 DSH 自带 Electron 内核跑任务；鲸鱼娘发行包自带 runtime）。

---

## 2. 要拷贝什么

**拷贝（必需）**

```
<插件目录>\        ← 整个插件目录（本机现在的位置，建议笔记本放同一路径）
```

里面已包含 Host 插件、浏览器面板、鲸鱼娘侧适配脚本、文档、自检脚本；**没有 node_modules，无第三方依赖**。

**不要拷贝（或自行评估）**

| 内容 | 原因 |
|---|---|
| `%USERPROFILE%\.dsh\whale-bridge\` | 本机的桥接数据：设置、任务历史、日志、**上游 API Key**、鲸鱼娘配置备份。新机器建议重新配置 |
| 本机鲸鱼娘的 `config.json` / `data\` | 那是本机的账号/记忆/Key；笔记本用她自己的 |
| `%USERPROFILE%\.dsh\profiles\desktop\` | 不要直接复制 profile；用安装脚本在笔记本重新挂载插件 |

## 3. 必须改的路径

插件默认值是按本机写的，笔记本路径不同时要改。两个位置二选一（推荐面板改，持久且不用碰文件）：

1. **面板改（推荐）**：装好后在 DSH 左栏「鲸鱼娘桥接」→「DSH 选项」里把**工作区**改成笔记本上的目录；「鲸鱼娘接入」卡片的路径由 `whaleDir` 设置决定（面板设置里可改，或直接改下面第 2 条）。
2. **改插件默认值**：`whale-dsh-bridge\cordis.patch.yml` 里 `config.workspace` / `config.whaleDir` 改成笔记本的路径，然后重装/重载插件。

安装脚本本身支持参数，不用改文件：

```powershell
cd <插件目录>
powershell -NoProfile -ExecutionPolicy Bypass -File .\install-dsh-plugin.ps1 `
  -ProfileDir "$env:USERPROFILE\.dsh\profiles\desktop" `
  -PluginDir  "<插件目录>" `
  -Port 8789
```

---

## 4. 安装步骤（笔记本上照着做）

1. **启动 DSH 桌面端**，确认能正常进界面。
2. **拷贝插件目录**到笔记本（建议同样 `<插件目录>`）。
3. **运行安装脚本**（上面那条命令）。
   - 它会：备份 profile `package.json` → 建 `node_modules\dsh-whale-bridge` junction → 把 `dsh-whale-bridge` 加进 `dsh.profile.bundles` → 等 HMR 重组 → 探测 `http://127.0.0.1:8789/api/health`。
   - 看到 `bridge is live` 即安装成功。
4. **刷新 DSH 页面**（Ctrl+R），左栏出现「鲸鱼娘桥接」。
5. **确认桥接**：浏览器打开 `http://127.0.0.1:8789/api/health` 应返回 JSON。
6. **配上游模型**：面板 →「高级」→ 填 baseUrl（默认 `https://api.deepseek.com`）/ Key / model（`deepseek-chat`）→ 保存。
   （如果鲸鱼娘原本已能聊天，也可以直接进入下一步，点接入时会自动继承她的服务商/Key。）
7. **接入鲸鱼娘**：面板「鲸鱼娘接入」→ 一键接入。会改鲸鱼娘的 `config.json`、`data/settings.json`，注入 `/debug` 卡片，并把她的请求超时放宽到 660 秒（适配最长 10 分钟的 DSH 任务）。
8. **启动鲸鱼娘**：点「打开鲸鱼娘网页」（会自动启动并在浏览器打开；已开着 bat 时只打开页面，不会重复启动）。
9. **验证**：
   - 网页聊天说一句闲聊，确认能正常回；
   - 说一件要动手的事（如「让 DSH 数一下工作区里有多少个 js 文件」），确认先收到状态播报、最后给出结果；
   - 群里 @ 她测试一次（微信桥接需她自己启动 `启动微信桥接.bat`，本机按约定**没做微信真实调试**）。

## 5. 验证清单

| 检查 | 期望 |
|---|---|
| `GET http://127.0.0.1:8789/api/health` | `{ok:true,...}` |
| `GET http://127.0.0.1:8789/api/state` | `status.whale.configured = true`、`status.dsh.profile.ready = true` |
| DSH 刷新后左栏 | 有「鲸鱼娘桥接」入口，点开有状态三卡 |
| 面板任务测试台跑「回答 1+1」 | 返回 `2` |
| 鲸鱼娘网页闲聊 | 正常回复 |
| 鲸鱼娘网页需要动手的消息 | 先出一句状态，再给 DSH 执行结果（最多 10 分钟） |
| 网页聊天「📎」上传文件后提问 | DSH 能读到文件内容并回答（文件落 `<工作区>\.whale-bridge\inbox\`） |
| 让 DSH 产出文件（如报告/表格） | 回复末尾出现 `📎 文件名` + 可点击的 `http://127.0.0.1:8789/files/...` 下载链接 |

也可以直接跑自带验收脚本（装好后）：

```powershell

node <插件目录>\test\files-unit.mjs      # 文件通道单元（不联网）

```

## 6. 升级与版本隔离（重要）

| 变化 | 要做什么 |
|---|---|
| 插件自己更新 | 直接替换目录内容；已链接的目录会被 HMR 识别（必要时刷新 DSH 页面） |
| DSH 升级 | 插件不写死 DSH 版本；任务跑不动时在面板点「重建任务 profile」（会从新版本 headless 模板重建 `whale-agent`） |
| 鲸鱼娘升级 | 重跑一次「接入鲸鱼娘」（或 `whale-side\install-whale-side.ps1` + 面板再接入一次）；她的 `config.json`/`data` 属用户数据升级不覆盖，`web/index.html` 的标记块会被覆盖需重注入 |
| 换机器 | 本任务书流程 |

关键约定：**插件代码只依赖 DSH 已文档化的 headless CLI 契约 + 鲸鱼娘的 config 结构，不 import 任何 `@deepseek-ai/*` 包，不改 DSH 安装目录，不改鲸鱼娘源码。**

## 7. 回滚

```powershell
# DSH 侧：移除链接与组合包条目（保留 ~/.dsh/whale-bridge 数据）
powershell -NoProfile -ExecutionPolicy Bypass -File .\uninstall-dsh-plugin.ps1

# 鲸鱼娘侧：还原 config.json / data/settings.json 备份、删除 /debug 标记块
powershell -NoProfile -ExecutionPolicy Bypass -File .\whale-side\revert-whale-side.ps1
```

## 8. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 点了「打开鲸鱼娘网页」没反应 | 旧版是用 `cmd start` 调浏览器，在 DSH 宿主进程里不生效、却误报「已打开」。已修：改为多种方式尝试，并用桥接 `/open` 跳板**确认浏览器真的打开**（实测可用方式为 `rundll32 url.dll,FileProtocolHandler`）；全部失败会明确提示手动打开地址 |
| 点了打开，bat 窗口没弹 | 设计如此：鲸鱼娘已在运行时**不会重复启动**；没在运行时桥接用后台方式启动（等价 `node server.js --no-browser`），窗口由浏览器负责。想看窗口就自己双击 `启动鲸鱼娘.bat` |
| 桥接端口不是 8789 | 8789 被占用会自动顺延并写回设置；面板显示的端口为准，鲸鱼娘接入地址也随之更新（重新点接入） |
| 任务跑不动 / 报没有 profile | 面板「重建任务 profile」 |
| 鲸鱼娘报 `request timeout` | 重新点「接入鲸鱼娘」（会把 `deepseek.timeoutMs` 抬到 660s） |
| 中文路径问题 | 鲸鱼娘解压路径必须纯英文（她自己对微信 UI 自动化的限制） |

## 9. 文件通道（v0.2.x：网页侧 + 微信侧；微信侧需主人明确授权）

> 需求：聊天里能「收文件给 DSH 处理」和「把 DSH 产物发回来」。参考本机 Hermes 的 media 设计（`gateway/platforms/base.py` 的 `MEDIA:` 出站标记 + token 化下载；入站附件提示），按本桥接场景简化实现。
>
> 注：实测本机 Hermes 并没有现成的 `[Shared attachment] file:` 短格式（原计划引自旧文档），我们保留这个**紧凑自定义标记**，两侧都由桥接控制，不依赖 Hermes。

**已实现（v0.2.0，本机真实链路验证通过）**

1. **DSH → 用户（出站）**
   - `dsh_task` 指令约定：交付文件时让 DSH 保存到 `<工作区>\.whale-bridge\outbox\`，并在最终文本输出 `MEDIA:<绝对路径>`（系统提示已内置；也支持自动扫描 outbox 新文件兜底）。
   - 桥接提取/校验（扩展名白名单、单文件 ≤20MB、敏感路径拒绝）后登记 token，在回复末尾追加：
     `📎 文件名（大小）` + `http://127.0.0.1:8789/files/<32hex>/file_<token8>.<ext>`（ASCII 短名，防鲸鱼娘重排/截断破坏链接）。
   - 聊天页注入脚本把 URL 渲染成可点击 `<a>`；若回复被切气泡导致链接丢失，脚本从原始 SSE 兜底补一条下载消息。
2. **用户 → DSH（入站）**
   - 聊天页注入「📎 上传」控件（`web/index.html` 带标记块，可回滚）；文件 base64 上传到 `POST /api/upload` → `.whale-bridge\inbox\`。
   - 下一条 `/api/chat` 的 text 末尾自动追加 `[Shared attachment] file: <绝对路径>`；桥接把它作为 system 提示给上游模型，模型把路径写进 `dsh_task`，DSH 直接读。
   - 只选文件不写字直接点发送也可以（脚本自动补一句，绕过鲸鱼娘空文本提前 return）。
3. **微信私聊/群聊（v0.2.x，需主人明确授权）**：由鲸鱼娘自己的 Python 微信桥接 `examples/wechatauto_bridge.py` 实现（改前务必备份，可回滚）：
   - 入站：微信「文件」消息（库里 type 是 `文件/链接/卡片`，XML 带 `<fileext>/<totallen>`）→ `MediaDownloader.download_file` 取本地路径，失败按 `<title>` 从 `<账号目录>\msg\file` 缓存兜底复制到 `data\wechat-files\` → 文本末尾追加 `[Shared attachment] file: <绝对路径>` 交给 DSH；图片也带落盘路径；用户自己打字的 marker 会被中和（防注入读任意文件）。
   - 出站：回复里的 `http://127.0.0.1:8789/files/...`（以及 DSH 工作区 `outbox` 本次新产出的文件兜底）→ 取文件到 `data\wechat-outbox\` → 文字发完后用 `uiautomation.SendKeys`（Ctrl+V 粘贴 + Enter）发成微信文件消息，数据库回读确认；确认不了清理草稿并回退发链接，不重复发文件。注意微信 4.x 上 `SendInput`/`gui._input.key` 无效，必须用 `uiautomation.SendKeys`。
   - 配置：`config.json` 的 `wechat.fileChannelIn / fileChannelOut / fileMaxMB`；自测钩子见插件 README（`WHALE_WECHAT_TEST_*` 环境变量，默认关）。
   - 微信升级后 `examples/wechatauto_bridge.py` 会被覆盖，需要重新打补丁（备份/回滚见插件 README）。
4. **安全**：只允许 inbox/outbox 与显式 MEDIA 路径；校验存在性/大小/扩展名/敏感目录；下载 token 化（随机 32 hex、24h 过期、不接受任意路径），不读取 `~/.dsh`（含桥接 settings/凭据）、`.ssh`、`.env`、私钥类文件。

**验收脚本**：`test/files-unit.mjs`（30 项）、`test/e2e-files.mjs`（真实 15 项）、`test/ui-file-channel.mjs`（无头 Chrome 17 项）。

**设置**：`settings.files = { enabled, autoOutbox, maxFileMB, linkTtlHours }`（`PUT /api/settings`）。

**后续可选**：面板/调试卡的图形化文件开关；多文件打包下载；微信侧大文件分块/更稳的附件发送链路。

## 10. DSH 原生模式（新鲸鱼娘，2026-11 起）

> 目标：第一手聊天直接进 DSH（不再让上游模型当聊天大脑），每个微信/网页聊天固定一个 DSH 会话，上下文天然稳定；发「新会话」可重开。

1. **给鲸鱼娘打补丁**（幂等、自动备份、可回滚）：
   ```bat
   "<鲸鱼娘>\runtime\node.exe" "<插件>\whale-side\patch-whale-native.mjs" --whale "<鲸鱼娘目录>"
   ```
   改的是 `src/llm.js`（请求带 `x-whale-chat` 头、本地 provider 超时 900s）和 `src/bot.js`（模型调用带 `chatKeyOf(msg)`）。**不动微信桥**（防检测封号）。
2. 重启鲸鱼娘服务：`"<鲸鱼娘>\runtime\node.exe" server.js --no-browser`。
3. DSH 面板 →「鲸鱼娘桥接」→「DSH 原生（新鲸鱼娘）」卡片：大脑切 `dsh` → 保存 → 点「同步到鲸鱼娘」（写回 provider=custom、`llm.baseUrl=http://127.0.0.1:8789/v1`）。
4. 验证：微信/网页发一句话应得到 DSH 会话回复；同一聊天追问能记住上下文；发「新会话」后不记得旧内容。面板「鲸鱼娘调试台」可看 system 提示词、记忆、功能开关并清空指定会话记忆。
5. 回滚：`--revert` 还原鲸鱼娘两文件 + 重启服务；插件 `PUT /api/brain {brain:'upstream'}` 回旧模式。
6. 注意：微信桥 `examples/wechatauto_bridge.py` 的文件通道补丁与本模式相互独立；本模式不要求改微信桥。

## 11. 当前已知限制

- 微信侧文件通道已实现（v0.2.x），但属于 UI 自动化：需要真实微信登录 + 桥接运行，发送时窗口可能短暂被置前；仅在主人明确授权时做真实验证；本插件自动测试不碰微信。`/debug` 卡片需要先启动鲸鱼娘网页服务。
- 文件通道：网页侧与微信侧都已做；面板任务测试台 `/api/task` 直连执行器，不登记下载链接；单文件默认 20MB、下载链接 24h 过期、桥接重启后已登记 token 失效（文件仍在磁盘）。
- 每个 DSH 任务默认是独立会话；连续任务需要模型判定续接（`continuity: auto`）或手动设「默认会话」。
- 单任务上限 10 分钟；超时/断开时桥接会终止 DSH 子进程，并用失败说明回复。
- 鲸鱼娘网页聊天的助手气泡是纯文本渲染；v0.2.0 起注入脚本会把下载 URL 渲染成可点击链接（升级鲸鱼娘后需重跑接入重新注入）。
